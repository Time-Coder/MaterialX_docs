# MaterialX 项目治理

- [English](../docs_en/GOVERNANCE.md)
- [简体中文](GOVERNANCE.md)

MaterialX 是 [学院软件基金会](https://www.aswf.io/) 的一个项目，依赖于 ASWF 治理政策，由 Linux 基金会支持。

MaterialX 项目维护一个技术指导委员会（TSC），对项目拥有最终权力。如项目章程所定义，TSC 的职责包括但不限于：

- 讨论、寻求共识，并在必要时对影响多个项目的 MaterialX 相关技术事项进行投票。
- MaterialX GitHub 存储库的维护和管理。
- 协调项目的技术方向。
- 协调有关 MaterialX 的营销、活动和沟通。

在 TSC 内部有两个关键子组：**投票成员**，承担维护 MaterialX 项目的正式责任，并在需要决策时投票；以及 **利益相关者**，代表行业中的特定团队和公司，在 MaterialX 讨论中代表他们发言。

### 投票成员

这些委员会成员负责积极为 MaterialX 项目做出贡献，无论是以开发代码、改进规范和文档、审查 GitHub 上的拉取请求，还是协助团队进行 MaterialX 集成的形式。虽然我们预计大多数决定将在 MaterialX TSC 中达成一致，但对于需要正式投票的决定，需要多数投票成员才能推进更改。

在 TSC 的投票成员中有两个选举产生的领导角色。任何投票 TSC 成员都可以表示有兴趣担任某个角色，或提名另一位成员担任。没有任期限制，一个人可以同时担任多个角色。如果 TSC 成员在任期完成之前辞去领导职务，应通过标准提名和投票程序选举继任者以完成剩余任期。领导角色包括：

- **主席**：此职位担任项目经理，组织会议并对项目管理提供监督。
- **TAC 代表**：此职位在 ASWF 技术咨询委员会会议上代表 MaterialX 项目。

### 利益相关者

这些委员会成员代表与 MaterialX 项目密切相关的团队或公司，并对其未来发展有强烈兴趣。利益相关者在 MaterialX 讨论中代表其团队或公司发言，提供指导项目所需的广泛视角。大多数新委员会成员从这个类别开始，它不需要他们承诺贡献或维护 MaterialX 项目，尽管鼓励他们这样做。

### TSC 提名和继任

任何关于增加 TSC 成员的提案都可以通过在 Slack 上联系当前 TSC 成员或在 TSC 会议上提出问题来提交。新 TSC 成员由 TSC 多数投票接受或拒绝。

如果 TSC 成员在较长时间内不定期参与或履行 TSC 成员期望的职责，TSC 可以通过多数投票要求该组织提交替代 TSC 成员，或将不活跃成员从 TSC 中移除。

TSC 成员可以在决定离开 TSC 时提名继任者，TSC 应通过投票确认或拒绝该提名。如果 departing 成员的继任者提名被 TSC 投票拒绝，departing 成员有权继续提名继任者，直到有一个继任者被 TSC 投票确认为止。如果 departing 成员未能或无法提名继任者，TSC 可以代表 departing 成员提名一个。

即使投票 TSC 成员更换雇主，也假定保留其成员资格。TSC 可以采取措施确保组织利益相关者代表不会变得严重不成比例，例如敦促失去其唯一 TSC 代表的组织提名新成员，或者如果太多成员都移动到同一个组织，则限制来自任何单一组织的成员总数。

### TSC 会议

所有 TSC 会议都旨在向公众开放，除非有合理的隐私需求。TSC 以视频电话会议的形式定期开会，频率由 TSC 认为适当。TSC 主席主持会议，或在其缺席时任命另一位 TSC 成员主持。日程安排和连接详细信息可以在公开的 [ASWF 会议日历](https://www.aswf.io/meeting-calendar/) 中找到。

在每次 TSC 会议之前，会议主席将与 TSC 成员和更广泛的社区在 ASWF Slack 的 MaterialX 频道上分享议程。TSC 成员也可以在每次会议开始前向议程中添加项目。会议主席负责确保记录会议纪要并发布在 Slack 上。
